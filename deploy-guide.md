# MindMirror - Free Deployment Guide

## What You Need
- GitHub account
- Render account
- Groq account
- No credit card required to start on the free plans / free tiers currently offered by those services

## Step 1 - Get Your Free Groq API Key
1. Go to https://console.groq.com
2. Sign up with Google, GitHub, or email
3. Open API keys and create a new key
4. Copy the key for the backend variables on Render

## Step 2 - Push to GitHub
```bash
git init
git add .
git commit -m "MindMirror initial commit"
git remote add origin https://github.com/YOURUSERNAME/mindmirror
git push -u origin main
```

## Step 3 - Deploy on Render
1. Go to https://render.com
2. Create a new Blueprint from your GitHub repo
3. Select the `mindmirror` repository
4. Render will detect `render.yaml` in the repository root
5. It will create the backend, frontend, and PostgreSQL resources

The backend uses a lightweight Dockerfile (`Dockerfile.render`) that excludes ML dependencies (PyTorch, Transformers, Whisper) because:
- Emotion analysis falls back to keyword-based detection when the ML models are absent
- Voice transcription gracefully returns empty
- This keeps the image ~200MB (vs ~1.5GB) and fits Render's free tier (512MB RAM)

## Step 4 - Set Environment Variables in Render
For the backend service, Render should create these from the Blueprint:

```text
AI_PROVIDER       = groq
GROQ_API_KEY      = set this in the Render dashboard (use "sync: false" in Blueprint)
WHISPER_MODEL     = tiny
HF_HOME           = /app/.cache/huggingface
DATABASE_URL      = auto-injected from Render Postgres (includes ?sslmode=require)
JWT_SECRET        = auto-generated by the Blueprint
FRONTEND_ORIGIN   = https://mindmirror-frontend.onrender.com
ENV_MODE          = production
VAPID_PRIVATE_KEY = set this in the Render dashboard (generate via openssl)
VAPID_PUBLIC_KEY  = set this in the Render dashboard
VAPID_CLAIM_EMAIL = mailto:admin@mindmirror.app
```

> **Important:** Set `GROQ_API_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_PUBLIC_KEY` in the Render dashboard after deploy. These are marked `sync: false` so they won't auto-sync from the repo.

If you prefer to set variables manually, use the same values above.

For the frontend service, the Blueprint sets:

```text
NEXT_PUBLIC_API_URL = https://mindmirror-backend.onrender.com
```

## Step 5 - PostgreSQL (Auto-provisioned)
1. Render creates the PostgreSQL database from the Blueprint definition
2. The `DATABASE_URL` env var (with `?sslmode=require`) is injected into the backend automatically
3. Alembic migrations run on every backend startup — no manual setup needed
4. Database runs on Render's private network (not exposed to the internet)

## Step 6 - Seed the Demo Data
After the backend is deployed and healthy, open the Render shell for the backend service and run:

```bash
python seed.py
```

The seed script creates 30 days of demo data with a 3-phase emotional arc.

## Step 7 - Get Your Public URLs
Render will give you public URLs for both services:

- Backend: `https://mindmirror-backend.onrender.com`
- Frontend: `https://mindmirror-frontend.onrender.com`

Health check is at `https://mindmirror-backend.onrender.com/health`.

## Extra Step — Generate VAPID Keys for Push Notifications
Push notifications require VAPID keys. Generate them locally:

```bash
# Generate VAPID keys using the command-line tool
pip install pywebpush
python -c "from pywebpush import webpush; from jose import jwt; import json; import base64; from cryptography.hazmat.primitives.asymmetric import ec; from cryptography.hazmat.primitives import serialization; key = ec.generate_private_key(ec.SECP256R1()); priv = base64.urlsafe_b64encode(key.private_bytes(serialization.Encoding.DER, serialization.PrivateFormat.PKCS8, serialization.NoEncryption())).rstrip('=').decode(); pub = base64.urlsafe_b64encode(key.public_key().public_bytes(serialization.Encoding.X962, serialization.PublicFormat.UncompressedPoint)).rstrip('=').decode(); print(f'VAPID_PRIVATE_KEY={priv}'); print(f'VAPID_PUBLIC_KEY={pub}')"
```

Or use the OpenSSL method:
```bash
# Generate EC private key
openssl ecparam -genkey -name prime256v1 -out vapid_private.pem

# Extract public key
openssl ec -in vapid_private.pem -pubout -out vapid_public.pem

# Base64-encode both (remove newlines and headers)
VAPID_PRIVATE_KEY=$(tail -n +2 vapid_private.pem | head -n -1 | tr -d '\n')
VAPID_PUBLIC_KEY=$(tail -n +2 vapid_public.pem | head -n -1 | tr -d '\n')
```

Set `VAPID_PRIVATE_KEY` and `VAPID_PUBLIC_KEY` in the Render dashboard for the backend service.

## Notes
- The backend Dockerfile (`Dockerfile.render`) skips PyTorch, Transformers, and Whisper to stay within Render free tier limits
- Emotion analysis falls back to keyword-based pattern matching (still detects 8 distortion types)
- Voice transcription is disabled on Render (returns empty) — no audio processing without Whisper
- ML models still work in local Docker development (the full `Dockerfile` is used with `docker compose`)
- If you upgrade Render to a paid plan, switch to the full `Dockerfile` for ML-powered features

## Free Tier Limits
- Render: confirms the current account limits in your Render dashboard
- Groq: confirms current request and rate limits in the Groq console
- PostgreSQL: free plan database sleeps after 15 min of inactivity (wakes on query, ~30s delay)
- Build minutes: 500 hours/month on free tier
